# Contributing to mzStack

Our long-term aim is to build and sustain mzStack as a community-driven effort. The initial specification, reference implementations and applications are a starting point. We welcome contributions from researchers, software developers and data-resource maintainers. You do not need to write code to contribute.

## Ways to contribute

- Share use cases and requirements for working with large-scale mass spectrometry datasets.
- Review the mzStack specification and suggest improvements to its clarity, consistency or interoperability.
- Improve documentation, examples and getting-started guidance.
- Test the Python and R reference implementations and associated applications, and report bugs or unexpected behaviour.
- Contribute focused improvements to the implementations and applications.

When describing a use case or suggesting a change, explain the problem you are trying to address and the outcome you would find useful. When reporting an implementation issue, include the version, steps to reproduce it, what you expected to happen and what actually happened.

## Contributing to individual repositories

Follow the contribution instructions and licensing terms in the relevant repository. Repository-specific guidance takes precedence over this general guide.

Discuss substantial changes with us before beginning implementation. Keep contributions focused, explain their purpose, update relevant documentation, and run the checks described by the repository. Include appropriate tests when changing behaviour.

Repository-specific setup and development guidance will be provided as the repositories are released.

## Code of conduct

All mzStack repositories and community spaces are covered by our [Code of Conduct](https://github.com/mzStack/.github/blob/main/CODE_OF_CONDUCT.md). Please read it before participating. It also explains how to report concerns privately.
